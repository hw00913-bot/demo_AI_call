# 业务场景与意向标签业务规则 (Business Rules)

本文件定义当前迭代 v1.1 的业务逻辑与交互约束。

## 意向标签管理规则

### 1. 标签排序移位规则
- 当管理员修改某供应商或本地标准标签的 `sort` 序号时，同一标签池/标签集内的其他标签排序将发生联动。
- 移位规则：受影响的其他标签会自动依次连续调整其 `sort` 排序，确保在同一层级内序号连续且唯一。

### 2. 大众通信标签手动映射规则
- 根据 PM 明确澄清，**大众通信的供应商标签（A-F级）首次启用时不启用任何基于关键词的自动映射算法**。
- 大众通信的 A-F 等级标签映射工作完全由超级管理员在意向标签管理页面中，通过界面下拉手动配置关联到系统本地标准标签上。
- 大众通信标签不从接口自动读取，由管理员在中台手工新增、编辑、删除、排序和启停；其到本地标签的关系同样只允许手动映射。

### 3. 停用保护规则
- 当供应商（如一知科技、中科金等）或特定的业务场景其状态被设置为禁用/停用（`status === 'disabled'`）时，属于该供应商或场景下的所有标签卡片和配置全部置灰。
- 在禁用状态下，新增、编辑、删除以及启用状态的勾选框等全部操作将被禁用（disabled）。

## 场景配置与数据规则

### 1. 权限控制规则
- 业务场景和意向标签的配置管理仅超级管理员可用。
- 前端界面的数据搜索与状态筛选均在前端进行实时数据过滤，无复杂后端鉴权。

### 2. 字段映射和异常处理规则
- 通话记录的大众通信 13 种状态码必须正确显示其对应的中文状态。如果捕获到 0-12 范围外的未知通话状态码，应退避显示其原状态码数值，不得显示空值或报错。中台通话状态在 23 项基础上新增“秒挂”“伪接通”以承接电声细分接通状态；进入中台统一统计、筛选或跨平台对账时，按完整中台状态归并：大众 `0→等待呼叫`、`1→已接通`、`4→无人接听`、`8→占线`、`3→拒接`、`5→空号`、`6→关机`、`7→停机`、`10→欠费`、`11/12→黑名单过滤`、`9→呼叫受限`、`2→线路拦截`；中科金 `7→已接通`、`5/11→无人接听`、`9→占线`、`13→空号`、`15→关机`、`14→停机`、`12→无法接通`、`8→呼叫受限`、`6→外呼失败`、`4→等待重呼`、`17→号码故障`、`18→线路故障`，其中 `1-未拨打`、`2-等待接听`、`3-接听中` 为过程态，不进入最终通话结果表；电声仅保留其直接回传状态与中台状态的映射关系（优先按 `answerStatus` 归并：`301→已接通`、`302→秒挂`、`303→伪接通`、`205→拒接`、`206→无人接听`，当 `answerStatus` 缺失或未知时用 `answerMainStatus=3→已接通`、`answerMainStatus=2→无法接通` 兜底），去除依据中台状态强行推断/强制映射的伪规则，电声无直接回传的状态均不进行映射；`待呼叫去重` 仅保留为中台/科大去重类状态，不承接大众 0-等待呼叫；大众通信当前 0-12 枚举对“无法接通、拦截规则、待呼叫去重、分机号错误、主叫欠费、呼损客户、外呼失败、转人工呼损、等待重呼、号码故障、线路故障”无直接对应回传状态；未知码归并为“未知状态”。
- 线索记录中如果存在未评级的意向等级（非 1-6 级），前端应显示为“未评级”。
- 大众任务的数据概览“意向分类”和“意向洞察”均按大众枚举展示完整等级名称：A-高意向、B-意向客户、C-潜在客户、D-一般意向、E-需再次跟进、F-号码无效；意向分类配置下拉也只能使用这 6 个枚举值；一知和中科金沿用原平台标签。
- 为保持原型可读性，接入大众通信的主要列表默认将大众通信数据置顶展示，包括外呼列表、业务场景、通话记录、线索记录、通话统计和计费统计；用户主动排序时以用户排序为准。

### 3. 大众通信任务规则（官方 API v2）

- 中台新建业务场景时关联任务标识 `uuid`、模型类型（大模型/小模型）和账号；模型和账号字段为中台业务场景表字段一致性保留，不用于控制外呼接口版本；不在中台重复编辑大众通信任务策略。
- 重呼、并发、呼叫时间、任务类型、线路和弹号顺序均在大众通信 SaaS 中配置。
- 大众通信外呼任务统一使用新版 2.0 外呼接口，原型中的大众任务均按 `task_type=7` 展示；中台不再兼容旧版 2.0 任务结构。
- 大众通信大模型统一使用 3.0 大模型接口口径；模型类型选择与接口版本解耦。
- 任务状态 `1=暂停中`、`2=执行中`、`3=等待执行`；中台卡片分别显示用户暂停、进行中和未开始。
- 计费统计主列表按截图保持精简展示：顶部备注说明“通话计费以客户接通为准，按分钟收费，未满 1 分钟按 1 分钟计费”；筛选区仅展示计费日期和租户名称；主表仅展示计费日期、租户名称、计费时长和操作。计费类型和智能平台只作为数据层归类字段，不在主列表展示。
- 外呼列表对大众通信任务保留与其他平台一致的”查看、编辑、更多”布局，但编辑、删除、暂停、终止、启动均置灰且不可点击；呼叫名单中的手动导入对所有平台开放（含大众通信），大众通信导入限制单次最多 100 条号码（对齐大众通信批量添加号码同步接口限制）；超出拦截提示拆分文件。
- 任务详情字段以新版 2.0 外呼任务编辑接口 GET `/agent-api/new/user/{user_id}/task/{task_id}/edit` 返回为准，仅读取 `new_task_extra`；接口未返回的字段统一显示 `-`。
- 大众任务详情交互与一知、中科金一致：沿用同一抽屉和“任务详情”Tab，以单列信息行展示 7 项接口业务字段；不展示接口未定义的“启动方式”、额外的完整接口字段展开区或中台外呼进度数据。
- “自动重拨设置”必须逐项展示新 2.0 接口的 `redial_enabled`、`redial_new_number_policy`、`redial_interval`、`redial_max_times`、`redial_conditions.hangup_cause` 和 `redial_conditions.da_status`；即使重呼关闭，也不隐藏接口已返回的其他配置。
- 通话记录通过 `uuid` 归集大众通信数据并支持按任务 ID 查询；通话统计按截图保持精简展示，仅提供呼叫时间和场景名称筛选，不展示智能平台、关联任务 ID 列或筛选项，统计结果仍是中台对同步通话记录的只读汇总。
- 大众通信通话详情遵循“通话结束回调 → 生成通话记录 → 通话详情查询”顺序：回调携带 `callid`，中台将同值作为 `recordid` 调用详情接口。未收到回调时不产生通话记录，因此详情页不提供“等待回调”状态。
- 录音播放地址只取通话结束回调中的录音链接；通话文本只取通话详情 `records`，其中 `question` 显示为客户发言，`answer_content` 显示为 AI 客服发言。文本按 `sequence` 排序，已有 `asrmessage_notify` 最终识别结果时必须过滤同句的 `asrprogress_notify` 中间结果，并清理 SSML 标签。
- 外呼结果中的“外呼小结”按来源优先级展示：先展示大众通话详情 `componet`（兼容 `component`）自定义组件中字段名为“通话总结/外呼总结/summary/call_summary”的内容；如果大众未返回总结，则展示百炼智能体提取的通话总结。外呼小结下方的意向标签固定取百炼智能体标签。
- 通话记录详情的“详细信息”按 PM 指定顺序展示：会话 id、用户号码、场景编码、场景名称、对话时长、通话开始时间、通话结束时间、通话结果、转人工状态、转人工时间、用户关注、意向标签、通话标签。其中场景编码和场景名称为关联中台场景信息；通话标签取通话详情 `componet/component` 中已返回值的非总结自定义字段名称，并以可换行胶囊展示；字段缺失时显示 `-`。
- 线索记录中的“最后回访记录”对应通话总结；大众通信线索优先展示通话详情 `componet/component` 自定义组件总结，缺失时展示百炼智能体提取的通话总结。
- 线索记录中，大众通信的“客户详细标签”同样取通话详情 `componet/component` 中已返回值的非总结自定义字段名称；线索内关联通话的“外呼结果”和“详细信息”必须与通话记录详情页保持同一套展示字段、总结优先级、意向标签来源和通话标签胶囊样式。
- 大众通信 `callid` 在页面统一展示为“会话 id”；`recordid=callid` 只作为内部详情查询规则，不在通话详情中单独展示“详情记录 ID”。
