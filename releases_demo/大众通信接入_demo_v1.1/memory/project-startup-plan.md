# 项目启动规划 (Project Startup Plan)

本规划文件记录“大众通信接入”智能外呼原型项目的基本目的、业务需求、页面结构和验收标准。经 PM 确认后冻结作为 S2 门禁依据，后续仅可通过 decisions.md 或 change-log.md 记录变更。

## 文件规则
- 本项目为一个前端静态演示原型，所有的核心页面及 Mock 数据均采用原生 HTML/CSS/JS 实现。
- 除非超级管理员标签维护外，不保留复杂的后端会话。页面间通过静态参数或前端 localStorage 共享必要状态。
- 原型流程中各阶段产物（包括 change-log、verification-log 等）存放在 memory/ 目录下。

## 启动来源
- 大众通信 API 接入规范（derived，包含通话状态码、意向等级和外呼任务字段）。
- 本地意向标签标准与业务规则基础原型（8 模块 + 标签/场景/计费业务规则）。

## 产品形态
- 现代化前端静态外呼演示系统。
- 采用 Sleek Dark Mode（深色模式）以及 HSL 柔和配色方案，配以微小的动效以呈现高级质感。
- 支持侧边栏导航和多页面流畅交互，便于展示不同供应商平台的数据及配置。

## 项目目的
- 演示在智能外呼平台中如何集成大众通信提供的呼叫能力。
- 演示通话记录/线索记录页如何展示和映射大众通信的 13 种通话状态码。
- 演示意向等级（A-F 级）在线索列表和标签管理中的流转、解析和展示方式。
- 演示超级管理员在前台手动配置并关联大众通信的 A-F 等级标签到本地标准意向标签的交互。

## 项目范围
- **开发基础**：基于底座项目 `意向标签管理_demo_v1.0` 进行迭代开发，保留底座原有的功能和已有的平台（如一知科技、中科金智能等），并列新增“大众通信”平台的接入与切换演示。
- **业务场景管理页**：新增“大众通信”为可用智能平台。新建/编辑表单参考中科金的简易结构，提供关联“大众通信任务 ID (uuid)”的输入关联框，不增加模型类型、线路等冗余下拉设置。
- **通话记录页**：新增“平台/供应商”筛选器（选项包括：全部、一知科技、中科金智能、大众通信等）。当筛选“大众通信”时，正确解析并展示 13 个通话状态码的中文名称。
- **线索记录页**：不增设筛选器，所有平台的线索并列显示。大众通信对应的线索可将其意向等级 1-6 正确解析并展示为 A-F。
- **意向标签管理页**：大众通信在首次启用或关联时，不进行关键词自动映射，其供应商标签的映射管理完全交由界面由管理员进行手动关联配置。

## 非本期范围
- 实际的软电话拨号条对接与语音流实时通信。
- 真正的数据库与后端 API 服务，全部使用前端 mock 模拟。
- 多角色的后台权限控制系统（仅在前端通过 UI 控制模拟超管模式）。
- 自动生成 annotations/annotations.js 标注代码（只作标注提示词准备）。

## UI 风格
- **整体配色**：Sleek Dark Mode（背景深邃，主色调选用协调的蓝色/青色渐变，辅以警告色和成功色）。
- **字体与排版**：使用系统无衬线字体，保持紧凑和呼吸感并存的边距。
- **交互动效**：按钮悬停微缩放，状态切换时淡入淡出，拖拽或移动标签时有过渡动画。

## 参考资料
- `SRC-001`：大众通信 API 字段及状态码列表（包括 13 个通话状态码，A-F 意向等级，以及 uuid 等任务字段）。
- `SRC-002`：意向标签基础原型及业务规则。

## 数据和字段来源
- **状态码 (call_status)**：0 等待呼叫、1 呼叫成功、2 运营商拦截、3 拒接、4 无应答/无人接听、5 空号、6 关机、7 停机、8 占线/用户正忙、9 呼入限制、10 欠费、11 黑名单、12 用户屏蔽。
- **意向等级 (intention_level)**：1=A级、2=B级、3=C级、4=D级、5=E级、6=F级。
- **外呼任务字段 (task_fields)**：包含 uuid (任务 id)、task_type (任务类型 6=2.0, 7=新版2.0)、name (任务名)、status_str (状态)、enable (启用状态)、create_datetime (创建时间)、maximumcall (最大呼叫量)、destination_extension (主叫分机)。

## 整体页面结构
- **主体布局**：侧边栏导航 + 右侧主内容区域。
- **主要页面**：
  1. `result-records.html`（通话记录）：通话记录页中新增平台筛选器。
  2. `result-clue.html`（线索记录）：展示意向等级（大众通信显示为 A-F，空值显示“未评级”）。
  3. `sys-scene.html`（业务场景）：智能平台新增“大众通信”，其表单简化关联。
  4. `sys-tags.html`（意向标签管理）：供应商列表加入大众通信，支持手动关联映射。

## 核心流程
- **外呼通话记录模拟与筛选**：用户在通话记录页筛选“大众通信”，可查看大众通信的 13 种通话状态码对应的中文名称，以及线索记录中的 A-F 意向等级。
- **意向标签手动映射与排序调整**：
  - 管理员在标签管理页手动配置大众通信（A-F）映射到本地标准标签。
  - 管理员手动修改某个意向标签的 sort 序号，其余相关标签自动依次调整位置。
  - 停用某个供应商/场景，该供应商或场景下的配置卡片全部置灰，并禁用新增、修改和删除操作。

## 验收方向
- 大众通信 13 个通话状态码均能在通话记录页面中正确筛选并映射展示为中文。
- 意向等级 1-6 级能在线索记录中对照显示为 A-F 等级。
- 大众通信意向标签管理完全支持手动关联映射，其排序移位和停用保护逻辑正常工作。
- 页面可以通过左侧导航栏自如切换，无死链或空白区。

## 约束和风险
- 目前大众通信的 13 码与意向 A-F 尚属于 "derived" 阶段，在后续如果收到飞书等渠道的权威直出修改，需要在 change-log 中记录并重构 mock 数据。
- 本地展示的“超级管理员”权限只在前端通过 UI 控制开关（LocalStorage 可切）进行演示，不进行真正后端的 Token 鉴权。
