## 项目概览

智能外呼中台的静态前端原型（HTML/JS/CSS）。无框架、无构建步骤、无包管理器。直接在浏览器中打开 `index.html` 即可。所有数据均为存储在全局 `window.Mock*` 变量中的 Mock 数据。本次迭代的核心任务为接入“大众通信”这一呼叫平台供应商。

## 运行方式

```bash
# 打开原型页面
open index.html

# 启动标注保存服务（用于将标注编辑持久化到文件，可选）
node tools/annotation-save-server.js --port=3457
```

## 项目执行边界

### 1. 代码修改约束
- **底座共存与保留**：本次迭代是在底座项目 `意向标签管理_demo_v1.0` 上的功能叠加。必须保留底座已有的供应商（一知科技、中科金智能、冰兰等）及其原有功能（排序移位、停用保护等），严禁将其裁剪或重构。
- **页面框架与路由**：新页面或数据注入需遵循 IIFE + `'use strict'` 并注册到 `window.Pages`。严禁在 `index.html` 外壳中直接插入各页面专用的 UI DOM 节点。

### 2. 大众通信接入规则
- **新增场景配置**：大众通信表单只关联任务 `uuid`。重呼、并发、呼叫时间、线路及其他任务策略均在大众通信 SaaS 中配置，中台不重复提供这些字段。
- **通话记录页筛选**：必须在通话记录页中提供平台/供应商筛选。大众通信的 13 种通话状态使用官方字段 `status` 解析，默认情况下不影响其他平台。
- **线索记录页展示**：线索记录页不新增筛选器，所有平台的线索在同一列表中并列展示。但当线索归属于“大众通信”时，对应的意向等级 1-6 级必须被解析并显示为 A-F 级。
- **意向标签映射**：大众通信在首次启用或关联时，禁止使用任何“一键自动映射”算法，其意向标签与本地标准标签的映射逻辑完全由管理员在界面上进行手动关联和修改。

### 3. 数据层与 Mock 限制
- 所有修改均应写在 `mock/data.js` 及相关的 `js/pages/*.js` 文件中，确保数据状态仅在前端刷新前临时保存。
- 不得重构与当前任务无关的模块（如租户管理、导航框架、公共工具函数等）。

## Loop 阶段预检

在项目的各个完成阶段（如 S4、S6、S7、S8、S9、Final），必须运行对应的预检脚本来校验代码规范和产物合法性：

```bash
# 检查当前项目是否满足特定阶段的门禁要求
python3 tools/loop_run.py check . --preflight-stage [s4|s6|s7|s8|s9|final]

# 在各阶段开发完成后，通过 complete 命令推进状态机阶段
python3 tools/loop_run.py complete . --stage [S2|S3|S4|S5|S6|S7|S8|S9]
```

所有的阶段推进命令会触发 `tools/loop_preflight.py` 的校验，如发现未解决的占位符、关键文件内容过短或缺少防伪日志，状态机将拒绝流转。遇到阻塞项请按命令提示和建议方案修复。
