## 规则

- 每个核心需求至少对应一条验收标准。
- 验收标准必须可观察、可验证。
- 不确定需求写入 `memory/open-items.md`，不要写入已确认验收项。
- `Status` 如使用 `n/a`、`deferred`、`descoped`、`skipped`、`不适用`、`已取消` 或 `跳过`，必须在 `Decision / Reason` 写明产品或范围决策原因。
